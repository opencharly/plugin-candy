# 2026.313.1445 — fix(candy): consume the in-process schemaparams.Generate and bump spec to v0.2026313.1428

## Summary

`opencharly/spec#299` replaced `schemaparams`'s `cue exp gengotypes` shell-out with an in-process CUE-Go-API generator. `Generate` now takes `(schemaDir, pkg)`; the `cueDir` argument and `GenerateWithCue*` are deleted. This repository holds that API's one Go call site, and it now calls the two-argument form.

The `cue` CLI is off this generation leg. The help text and the `candy` skill body said it was provisioned into the charly cache; both are corrected. The pinned `cue` CLI remains the authoring tool for schema sources, and nothing in this module calls it on the generation path.

**Why the `sdk` bump is in this diff.** The `spec` bump alone does not compile here. This module's old `sdk` pin (`v0.2026280.2246`) predates spec's Kubernetes schema changes, and `sdk/vmshared/spec_aliases.go` references `spec.KubernetesGatewayAPI` and five sibling names that no longer exist in spec `v0.2026313.1428`; `sdk/kit` imports `sdk/vmshared`, so `go build ./...` fails with `undefined: spec.KubernetesGatewayAPI`. `sdk v0.2026309.2334` is the version `charly` already pins, and with it the module builds, vets and tests green. Without the bump the pin would not build, so it is part of the consumer change, not a separate leg.

**A clean regeneration is a no-op wherever the committed projection is current.** The same pipeline was run over every materialized plugin checkout at its own `origin/main` (120 repositories; 66 candies with a committed `candy/<name>/params/cue_types_gen.go`):

```

```

For all 18 that differ, the OLD pipeline (spec `v0.2026281.933`, shelling out to the pinned `cue` v0.16.1) and the NEW in-process generator produce byte-identical output (`cmp` rc=0 on all 18/18). So the new generator introduces none of that difference — each of the 18 is a committed projection that is older than its own schema, the set already tracked on `opencharly/opencharly#463` and in the per-repo issues. The test arm that covers the wrap end to end, `TestParamsRealPipelineRunsThroughTheVerb`, now runs the real in-process pipeline and fails rather than skips when it cannot.

The `charly`-side witness (`check-commands-local`, in `opencharly/charly`) resolves `command:candy` from charly's own pin, not from this branch; it builds against this repository's released tag on the next leg of `opencharly/opencharly#950`, which is the pin bump. This repository declares no bed of its own (`charly.yml` is `discover:` only), so its gate is the one pasted above.
