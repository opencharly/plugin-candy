# 2026.281.0833 — feat(candy): `charly candy params` — regenerate a plugin's params with nothing but charly

## Summary

`opencharly/charly#829`: **`charly candy params <candy>`** — regenerate a plugin candy's Go params from its own `candy/<name>/schema/*.cue`, using nothing but the `charly` binary.

**Why it exists.** A plugin candy's `schema/*.cue` is a **published** surface: `charly docs generate` renders it into `reference/plugin/<plugin>/plugin-*.md`. R4a requires every command such a page tells a reader to run to work with **nothing but the `charly` binary installed** — and until now no command could: regenerating a plugin's params meant `cd`-ing into a `spec` checkout and running `internal/schemagen` plus `cue exp gengotypes`, so the pages had to publish either a forbidden path or nothing. This verb is that missing command, and it ships *inside* the binary: `plugin-candy` is compiled in and owns `command:candy`, so R4a's property is structural rather than promised.

**The pipeline, with each step's contract named (R3 — one home each):**

| step | contract |
|---|---|
| concatenate `candy/<name>/schema/*.cue` | `spec/schemaconcat` |
| head it `package params` + `@go(params)` | this package (the header IS the contract) |
| `cue exp gengotypes` | `spec/cuetoolchain` — the pin **and** the fetcher |
| double every json tag with a yaml tag | `spec/schemaretag` |
| write `candy/<name>/params/cue_types_gen.go` | this package |

The toolchain is **provisioned, never assumed**: `ensureCue` calls `cuetoolchain.Ensure(cacheDir)` — the ONE fetcher, shared with spec's own `bootstrap-cue` task — which accepts a cached binary only if it **reports the pinned version**, verifies the sha256 **before** extracting anything, writes atomically, and fails loudly with the remedy for an unpinned arch. **This file carries no fetcher of its own**: an earlier draft did (~120 lines of `net/http` + tar), and deleting it is what makes the pin one home instead of three. The pinned toolchain and its version are named in `--help` and in the log line on first provision.

**`--check` is the drift gate a plugin repo's CI runs.** It compares the **committed file against the pipeline OUTPUT** — never a grep, never a hash of a previous run — and exits non-zero naming the file and the fix. `--schema/--pkg/--out` drives a schema that is not a candy's, which is the SAME mechanism the next leg uses to produce spec's own generated file through this verb.

**Rule 11.** The `candy-skill:` entity — the projected `/charly-candy-cli:candy`, i.e. the guidance surface a reader actually reads — now documents the command, the four contracts, the pin and the CI drift gate. That, plus this verb's own help, is what replaces the published recipe.

**Files (6, +505/−26):** `params.go` (+224), `params_test.go` (+232), `charly.yml` (+15/−2, the skill entity), `command.go` (+6/−1, the dispatch and usage), `go.mod` (+10/−5), `go.sum` (+18/−18).

**Pins, and what is NOT in this diff:** `spec v0.2026281.817` — verified, that tag points at spec#210's merge commit `c5b16ba2` and the module proxy serves it — and `sdk v0.2026280.2246` (required: the previous sdk pin is incompatible with current spec). **There is no `replace` in this diff** (`git diff origin/main...HEAD | grep -c '^+replace'` → `0`): the module resolves both dependencies from the proxy. During development the module *did* carry a dev-only `replace` to a local spec worktree, because the tag carrying `schemaconcat`/`schemaretag`/`cuetoolchain` did not exist yet — it was dropped before the commit, deliberately, since a `replace` in a pin bump reads as a pin bypass and should.

- **`TestParamsCheckGoesRedOnDrift` is the R7 proof for the gate**: a committed projection that differs from the pipeline output makes `--check` exit non-zero, name the file, say **STALE**, and write nothing (the test asserts the file is untouched afterwards). A check that cannot fail is the defect this campaign has produced repeatedly, so this arm mutates the file and watches the check go red.
- The wiring arms run against a **stub toolchain** (deterministic, no network): concat+header+retag → write; the no-op property (mtime unchanged on a clean regeneration); an empty schema directory failing loudly; `--check` on a missing projection naming it.

It passed here — it provisioned `cue v0.16.1` — and it **skips visibly** where the release cannot be provisioned, rather than substituting a fake.
